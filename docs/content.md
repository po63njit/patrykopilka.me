# Editing content

## Pages and images

- **Home:** `apps/web/src/components/HomeContent.astro`.
- **About:** `apps/web/src/components/AboutContent.astro`; its page metadata is in `src/pages/about.astro`.
- **Projects:** `apps/web/src/pages/projects.astro`. Entries are intentionally placeholders. Earlier project markup is preserved in `docs/archive/projects-before-cleanup.astro.txt`.
- **Résumé:** `apps/web/src/pages/resume.astro`, with experience data in `apps/web/src/data/experience.ts`. Keep the current approved public summary intact unless a replacement is approved; do not infer employment details.
- **Navigation, shared metadata, footer:** `apps/web/src/layouts/BaseLayout.astro`.
- **Shared styles:** `apps/web/src/styles/global.scss`; components also contain scoped styles.

Paths beginning `src/` above are relative to `apps/web/`.

Use `apps/web/public/` for files that need stable URLs, such as `/images/example.svg`. Use `apps/web/src/assets/` for imported images processed by Astro. The orbital artwork comes from `planet-pack.png`; `PlanetLink.astro` crops four regions from a shared generated WebP. Changing that image's layout requires updating its viewports and ring clipping path.

The homepage's motion lives in `OrbitScene.astro`, `MatrixWaves.astro`, and `src/scripts/`. Preserve keyboard navigation, the shared Pause/Resume control, reduced-motion behavior, and the [wave attribution](matrix-waves.md).

## Add or revise an article

Keep new article source and drafts in the separate private content repository, not this public repository. Follow [private article publishing](private-articles.md) for its manifest, production-only build access, local preview, and unpublishing.

The existing Hello World note remains at `apps/web/src/content/blog/hello-world.mdx`. The ignored `private/` subdirectory is generated by the preparation script. Do not edit or force-add generated manuscripts. The blog uses `BlogLayout.astro` and `ledger-blog.css`, independently of the main portfolio's layout and styles.

The collection schema requires `title` and `date`. New private manuscripts also require an explicit `slug` and `draft: false` before the production importer will accept them. The private `published.json` manifest is the publication allowlist; drafts must not appear there.

The homepage shows the newest published post, and `/blog/` lists all published posts newest first. Tags do not control inclusion. Future dates do **not** schedule publication; a manifest-listed article with `draft: false` appears on the next successful production build.

## Content tests

Public CI intentionally builds only public theme content. For a local integration build with private content, run the normal checks and set `BLOG_EXPECT_ARTICLES` to the comma-separated manifest slugs when running `test:build`. Keep the checks for absent review/source routes, working links/assets, canonical URLs, and approved experience wording. Never copy real manuscript text into public fixtures or CI artifacts.
